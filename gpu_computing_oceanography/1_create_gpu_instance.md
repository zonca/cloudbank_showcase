# 1 - Create a GPU Instance on Google Cloud

Goal: Create a GPU-enabled virtual machine instance on Google Cloud Platform to run GPU-accelerated Julia ocean modeling simulations.

## Prerequisites
- CloudBank will create the Google account for you automatically.
- A desktop browser. On Chromebooks, open an Incognito window first to ensure you use the CloudBank-generated Google account.

## Login to the Google Cloud Console
1) Open the login page: https://www.cloudbank.org/billing-account-access (Incognito if on Chromebook).
2) In the table under **Public Cloud Web Console Login**, click the **Login** button in the **Google Cloud Platform** row.
3) When prompted, continue with the Google account generated by CloudBank (no need to supply your own).
4) You should land in the Google Cloud Console for your assigned project. In the top bar, note the active project name/ID; we will need it for creating the VM instance.

## Enable Compute Engine API
1) Open the Compute Engine page: `Navigation menu ▸ Compute Engine ▸ VM instances`.
2) If prompted, click **ENABLE** to turn on the Compute Engine API. Wait until the page refreshes.

## Connect with Cloud Shell
We'll create the GPU instance using Gemini AI assistant in Cloud Shell. Open Cloud Shell by clicking the terminal icon at the very top of the screen labeled **Activate Cloud Shell**.

## Create the GPU instance with Gemini

### Step 1: Enable Compute Engine API
1) In Cloud Shell, type `gemini` to activate the Gemini AI assistant
2) Ask Gemini to enable the Compute Engine API:
```
I need to enable the Compute Engine API. Please run the command to enable it for me.
```

### Step 2: Verify GPU availability
Ask Gemini to check GPU availability:
```
I need to create a GPU instance with NVIDIA Tesla T4. Please check if the T4 GPU is available in zone us-west1-b by listing the accelerator types.
```

### Step 3: Create the GPU instance
Ask Gemini to create the instance with these specifications:
```
I need to create a GPU instance with:
- Name: julia-ocean-gpu
- Zone: us-west1-b
- Machine type: n1-standard-4
- GPU: nvidia-tesla-t4 (1 GPU)
- Image: ubuntu-2204-lts
- Boot disk: 200GB SSD
- Maintenance policy: TERMINATE
- Auto-install NVIDIA drivers via metadata

Please create this instance using gcloud compute instances create.
```

**Expected Gemini response:**
```
The instance julia-ocean-gpu has been created successfully in us-west1-b.

I've configured the instance with the following specifications:
 - Machine Type: n1-standard-4 (x86)
 - GPU: 1x nvidia-tesla-t4
 - Image: ubuntu-2204-lts (x86_64). Note that I used the x86 version instead of arm64 because the T4 accelerator and N1 machine family are x86-based.
 - Boot Disk: 200GB SSD (pd-ssd).
 - NVIDIA Drivers: A startup script was added to automatically install the nvidia-driver-535 package.

You can monitor the driver installation progress by checking the serial console output or by SSHing into the instance (gcloud compute ssh julia-ocean-gpu --zone=us-west1-b) and running tail -f /var/log/syslog. Once complete, you can verify the installation with nvidia-smi.
```

**Note:** This creates:
- An Ubuntu 22.04 LTS x86_64 instance with 4 vCPUs and 15 GB RAM
- One NVIDIA Tesla T4 GPU (16 GB VRAM)
- 200 GB SSD storage for data and packages
- Auto-installation of NVIDIA drivers via startup script

### Step 4: Verify instance status
Ask Gemini to check the instance status:
```
Please verify that the instance julia-ocean-gpu in zone us-west1-b is running and show me its details including GPU status.
```

You should see the instance status as `RUNNING` with the T4 accelerator attached.

### Step 5: Verify GPU installation
Ask Gemini to check the GPU status on the server:
```
Show me the output of nvidia-smi on the server.
```

**Expected Gemini response:**
```
I'll check the nvidia-smi output for you.

[... shows nvidia-smi output with Tesla T4 GPU, 15360 MiB memory, CUDA 12.x ...]
```

This confirms:
- GPU: Tesla T4 detected
- Driver installed and running
- 15360 MiB (~15 GB) GPU memory available
- CUDA Version: 12.x (compatible with CUDA.jl requirements)

### Step 6: Install Julia
Ask Gemini to install Julia using Juliaup:
```
SSH into the server and install Julia using Juliaup. First run the curl command to install Juliaup, then add Julia version 1.11 and set it as default.
```

**Julia installation commands:**
```bash
curl -fsSL https://install.julialang.org | sh
source ~/.bashrc
juliaup add 1.11
juliaup default 1.11
```

### Step 7: Verify Julia installation
Ask Gemini to check the Julia version:
```
Show me the Julia version on the server.
```

Expected output: `julia version 1.11.x`

### Step 8: Install Jupyter
Ask Gemini to install Jupyter using conda:
```
SSH into the server and install Jupyter using conda.
```

**Installation command:**
```bash
conda install -y jupyter
```

### Step 9: Install Julia packages
Ask Gemini to set up the Julia environment with the required packages:
```
SSH into the server and activate the current directory, then add these Julia packages: Oceananigans v0.99.0, Reactant, Enzyme, CUDA, and IJulia.
```

**Expected Gemini response:**
```
The Julia environment on julia-ocean-gpu is now fully set up.

Summary:
 - Project Activated: Root directory ~ (Home).
 - Installed Packages:
     - Oceananigans v0.99.0 (with CUDA and Reactant extensions)
     - Reactant
     - Enzyme
     - CUDA
     - IJulia (built and ready for Jupyter)

Important Note: Oceananigans emitted a warning about being tested primarily on Julia v1.10, but it successfully precompiled for your v1.11.9 installation.
```

### Step 10: Launch Jupyter notebook
Ask Gemini to start Jupyter:
```
SSH into the server and launch Jupyter notebook using IJulia. Make it run in detached mode so it stays running in the background.
```

**Julia command:**
```bash
julia -e "using IJulia; notebook(dir=pwd(), detached=true)"
```

## Next steps - Choose your access method

Now your GPU instance is ready! Choose one of these methods to access the Jupyter notebook:

**Option 1: Browser-based Jupyter**
- Simpler setup, works in any browser
- See tutorial: [`2_access_jupyter_browser.md`](2_access_jupyter_browser.md)
- Best for: Quick access, Chromebooks, mobile devices

**Option 2: VS Code Remote**
- Full IDE experience with debugging and IntelliSense
- See tutorial: [`2_access_jupyter_vscode.md`](2_access_jupyter_vscode.md)
- Best for: Serious development, debugging, advanced users

Both methods provide full access to the GPU-accelerated Julia environment and the ocean modeling notebook.

## Cleanup
**Remember to delete the instance when you're done to avoid ongoing charges:**

```bash
# Run this from Cloud Shell (not inside the instance)
gcloud compute instances stop julia-ocean-gpu --zone=us-west1-b
gcloud compute instances delete julia-ocean-gpu --zone=us-west1-b
```
